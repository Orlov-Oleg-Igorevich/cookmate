## Приёмочные сценарии безопасности
| ID | Требование | Тип | Исходные условия | Действия | Ожидаемый ответ | Ожидаемое состояние данных | Статус выполнения |
|---|---|---|---|---|---|---|---|
| AT_01 | SEC-04 | Позитивный | 1) Пользователь авторизован в приложении.<br> 2) В локальной БД присутствуют закешированные рецепты и список «Избранное».<br> 3) В защищённом хранилище (Keychain/Keystore) находится валидный JWT-токен. | 1)Пользователь открывает экран настроек профиля.<br> 2) Нажимает кнопку «Выйти из аккаунта».<br> 3) Подтверждает действие во всплывающем диалоге. | 1) Приложение перенаправляет пользователя на экран входа (Login Screen).<br> 2) Отображается уведомление об успешном выходе. | 1) Токен удалён из защищённого хранилища.<br> 2) Локальная БД очищена от пользовательских данных (избранное, история запросов).<br> 3) Попытка программно получить токен возвращает null или ошибку отсутствия данных. | Запланирован (механизм logout будет реализован в v0.3). |
| AT_02 | SEC-03 | Негативный | 1) Пользователь авторизован, токен присутствует в защищенном хранилище.<br> 2) Приложение принудительно закрыто через системный диспетчер задач (swipe away) без нажатия кнопки «Выход». | 1)Принудительное завершение процесса приложения ОС.<br> 2) Повторный запуск приложения через иконку.<br> 3) Попытка чтения токена из защищённого хранилища сторонним тестовым скриптом (на эмуляторе с root). | 1) Приложение запускается и восстанавливает сессию (если токен валиден) ИЛИ предлагает войти (если токен истёк).<br> 2) Сторонний скрипт НЕ получает plaintext-значение токена (доступ запрещён ОС или данные зашифрованы). | 1) Токен остаётся в хранилище только если сессия активна. 2) Файловая система не содержит копий токена в открытом виде. | Запланирован |
| AT_03 | SEC-06 | Позитивный | 1) Пользователь находится на экране распознавания.<br> 2) В галерее устройства есть корректное фото продуктов (JPEG, 1 МБ). | 1) Нажатие кнопки «Загрузить фото».<br> 2) Выбор файла из галереи.<br> 3) Автоматическая проверка размера и формата клиентом.<br> 4) Отправка POST-запроса на /api/recognize. | 1) Индикатор загрузки активен.<br> 2) Через 2-3 секунды отображается экран с распознанными продуктами.<br> 4) В сетевом мониторе виден успешный ответ 200 OK. | 1) Временный файл в кэше приложения создан и успешно передан. 2) После получения ответа временный файл удалён или помечен для очистки GC. | Запланирован |
| AT_04 | SEC-06 | Негативный | Пользователь пытается загрузить файл размером 15 МБ или форматом .exe / .pdf. | 1) Нажатие кнопки «Загрузить фото».<br> 2) Выбор недопустимого файла.<br> 3) Срабатывание клиентского валидатора. | 1) Сетевой запрос НЕ формируется (нет исходящего трафика на /api/recognize).<br> 2) На экране отображается toast/snackbar: «Неподдерживаемый формат или размер файла (макс. 2 МБ)».<br> 3) Экран распознавания остаётся активным, пользователь может выбрать другой файл. | 1) Временный файл либо не создаётся, либо немедленно удаляется.<br> 2) Состояние UI не переходит в режим загрузки. | Запланирован |
| AT-05 | SEC-8 | Позитивный | 1) Пользователь находится на экране редактирования распознанного списка продуктов.<br> 2) Список содержит корректные названия ингредиентов (например, «помидоры», «базилик»). | 1) Пользователь добавляет новый продукт, вводя текст «Молоко»<br> 2) Нажимает кнопку «Обновить рецепты».<br> 3) Приложение выполняет локальную валидацию строки.<br> 3) Формируется и отправляется POST-запрос на /api/search с телом {"ingredients": ["помидоры", "базилик", "Молоко"]}. | 1) Индикатор загрузки активен.<br> 2) Через 1-2 секунды отображается обновленный список рецептов.<br> 3) В сетевом мониторе видно, что тело запроса содержит ровно ту строку, которую ввел пользователь, без искажений. | 1) Локальный список продуктов обновлен.<br> 2) Сервер вернул 200 OK и актуальный список рецептов. 3) В логах приложения нет ошибок валидации. | Запланирован |
| AT_06 | SEC-8 | Негативный | Пользователь пытается ввести в поле продукта строку: <script>alert('xss')</script> или строку длиной 300 символов, содержащую управляющие символы \n\r\t. | 1) Вставка вредоносной/некорректной строки в поле редактирования.<br> 2) Нажатие кнопки «Обновить рецепты».<br> 3) Срабатывание клиентского санитайзера/валидатора. | 1) Сетевой запрос НЕ формируется (в сниффере отсутствует POST на /api/search).<br> 2) Поле ввода подсвечивается красным или появляется toast: «Недопустимые символы или превышена длина (макс. 50 симв.)».<br> 3) Кнопка обновления остается активной, но действие блокируется до исправления ввода. | 1) Локальный список продуктов не изменяется (вредоносная строка не добавляется).<br> 2) Список рецептов на экране остается прежним (не происходит перезагрузки с потенциально опасными данными).<br> 3) В памяти приложения не сохраняется введенная вредоносная строка. | Запланирован |
