## 1. Номер и название индивидуального варианта
__Вариант__: Индивидуальный проект.  
__Описание__: Мобильное приложение __«Cookmate»__ для распознавания продуктов и подбора рецептов.
## 2. Проблема, которую решает система
Пользователи часто имеют набор продуктов, но не знают, что из них можно приготовить. Ручной поиск рецептов неудобен, а ввод ингредиентов текстом занимает много времени. Система решает проблему быстрого поиска кулинарных решений путем автоматического распознавания продуктов на фотографии и формирования персонализированной подборки рецептов с возможностью сохранения избранного.
## 3. Пользователи
* __Неаутентифицированный пользователь (Гость)__: Использует базовый функционал (фото, поиск), но данные хранятся только локально и могут быть утеряны.
* __Авторизованный пользователь__: Имеет учетную запись, может синхронизировать избранное между устройствами, имеет доступ к истории запросов на сервере.
* __Администратор мобильного приложения (Разработчик/DevOps)__: Отвечает за выпуск обновлений, конфигурацию API-ключей и мониторинг работоспособности клиента.
## 4. Основные функции

| ID | Функция | Кто использует | Основные данные |
|---|--------|-----|---|
| F_01 | Загрузка изображения (камера/галерея) и отправка на распознавание | Все пользователи | Бинарные данные изображения (JPEG/PNG), метаданные |
| F_02 | Просмотр и редактирование распознанного списка продуктов | Все пользователи | Список текстовых строк (ингредиенты) |
| F_03 | Получение и отображение списка рекомендованных рецептов | Все пользователи | JSON-объекты рецептов (название, фото, ингредиенты, шаги) |
| F_04 | Управление списком «Избранное» (добавление/удаление) | Авторизованный пользователь | ID рецепта, идентификатор пользователя, timestamp |
| F_05 | Аутентификация и управление сессией (вход/выход/токен) | Гость / Авторизованный | Учетные данные (логин/пароль), JWT-токен |
| F_06 | Просмотр истории последних поисковых запросов | Все пользователи | Кэш локальных запросов, ссылки на ранее полученные рецепты |
## 5. Компоненты внутри границ проекта
__В границы проекта (мобильного приложения) входят__:
* __Клиентское приложение (UI/Logic)__: Код интерфейса, бизнес-логика обработки состояний, навигация.
* __Менеджер безопасного хранения__: Модуль работы с защищенным хранилищем ОС (Android Keystore / iOS Keychain) для токенов и чувствительных данных.
* __Сетевой модуль (API Client)__: Компонент, отвечающий за формирование HTTPS-запросов, обработку ответов и управление таймаутами.
* __Модуль работы с медиа__: Компонент, запрашивающий разрешения у ОС и получающий доступ к камере/файловой системе.
* __Конфигурация приложения__: Файлы настроек (endpoint'ы, публичные ключи, флаги фич).
## 6. Внешние системы
* __Backend API (Сервис рецептов)__: Внешний сервер, принимающий изображения, выполняющий распознавание (ML-модель) и возвращающий список рецептов. Приложение ему доверяет, но не управляет им.
* __Операционная система (OS)__: Предоставляет аппаратные ресурсы (камера, GPS, сеть) и системные сервисы безопасности (биометрия, шифрованное хранилище).
* __Сервис аутентификации (Auth Service)__: Встроенный в бэкенд сервис выдачи токенов доступа.
## 7. Ограничения учебной реализации
* Платежные функции и подписки отсутствуют.
* Защита от реверс-инжиниринга (обфускация, root-detection) находится на этапе проектирования и не реализована в коде v0.2.
* Обработка ошибок сети ограничивается базовыми сообщениями для пользователя без сложной логики повторных попыток (retry policy).
* Тестирование проводится на эмуляторах и ограниченном парке физических устройств.
* Реальные персональные данные и платежная информация не обрабатываются.
