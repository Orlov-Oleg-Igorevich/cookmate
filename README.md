# Cookmate Mobile App — Secure Development Project

## О проекте
Мобильное приложение для распознавания продуктов по фото и подбора рецептов.
Данный репозиторий содержит документацию по безопасности, разработанную в рамках дисциплины «Основы разработки защищённого ПО».

**Текущая версия:** v0.2  
**Роль в команде:** Разработчик мобильной версии (Mobile Client Security Owner)

## Версия v0.2: Результаты лабораторной работы №2

В данной версии зафиксирована полная спецификация требований безопасности для мобильного клиента. Реализация механизмов защиты запланирована на последующие этапы.

### 🔒 Ключевые особенности модели безопасности v0.2

1.  **Фокус на клиентской защите:** Требования SEC-01–SEC-08 проверяемы без работающего бэкенда (валидация ввода, работа с Keychain, очистка памяти).
2.  **Изоляция медиаданных:** Фотографии пользователей никогда не попадают в публичную галерею (SEC-02) и удаляются сразу после отправки (SEC-07).
3.  **Защита от инъекций на клиенте:** Санитайзинг ввода продуктов (SEC-8) предотвращает передачу вредоносных payload'ов даже при компрометации сервера.
4.  **Процессные гарантии:** Секреты исключены из Git (SEC-11), критический код проходит обязательный Code Review (SEC-12).

### ⏳ Что будет реализовано в следующих версиях

*   **v0.3:** Интеграция Android Keystore / iOS Keychain, реализация logout-логики.
*   **v0.4:** Внедрение валидатора схем JSON-ответов.
*   **v0.5:** Автоматизация приёмочных тестов для сценариев AT-01...AT-06.

> **Важно:** Все сценарии в `acceptance_scenarios.md` имеют статус «Запланирован». Это соответствует методике: v0.2 фиксирует *требования*, а не *реализацию*. Ожидаемые результаты тестирования приведены как спецификация будущего поведения системы.

## Как использовать документацию

1.  Для проверки полноты покрытия используйте таблицу прослеживаемости в конце `acceptance_scenarios.md`.
2.  При реализации каждого механизма обращайтесь к соответствующему требованию в `security_requirements.md` — там указаны точные критерии приёмки.
3.  Перед каждым коммитом проверяйте соответствие матрице доступа из `access_matrix.md`.
